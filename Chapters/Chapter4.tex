\chapter{Ensayos y resultados} % Main chapter title

En este capítulo se presentan las pruebas y ensayos realizados sobre el sistema de monitoreo y gestión  de cultivos hidropónicos verticales desarrollado.  
El objetivo principal fue verificar el correcto funcionamiento del hardware y firmware, así como validar el cumplimiento de los requerimientos funcionales definidos en las etapas de diseño.
Cabe destacar que en este capítulo se presentan casos de prueba representativos, seleccionados de acuerdo con su relevancia para demostrar el funcionamiento del sistema. La metodología descrita se aplicó de manera consistente en todos los ensayos realizados.

\subsubsection{Arquitectura pub/sub}
La validación del sistema de mensajería confirmó la correcta distribución de mensajes a través de un buffer estático, donde cada suscriptor se identifica mediante su ID de hilo. Las pruebas demostraron una gestión adecuada de semáforos durante la publicación y suscripción, lo que evita condiciones de carrera. Se comprobó la entrega confiable a múltiples destinatarios con preservación de la integridad de la información.


Como se muestra en la figura \ref{fig:buffer_overflow}, cuando el buffer alcanza su capacidad máxima, el sistema descarta automáticamente los mensajes más antiguos sin interrumpir el flujo de comunicación. Este comportamiento se observa claramente al triplicar el tiempo entre lecturas, lo que permite verificar el correcto manejo de desbordamiento.
Finalmente, se estableció una relación 1:1 entre publicadores y suscriptores, lo que permitió mantener estable cada canal y garantizar un flujo de información equilibrado.

\subsubsection{API REST con Postman}
Se desarrollaron pruebas de integración para los endpoints REST expuestos por el sistema, organizados por funcionalidad.
A continuacion se listan los endpoints disponibles.

\begin{itemize}
    \item \textbf{Autenticación}
    \begin{itemize}
        \item \texttt{POST /v1/login} : Autenticación de usuario
    \end{itemize}
    
    \item \textbf{Estado del Sistema}
    \begin{itemize}
        \item \texttt{GET /v1/status} : Estado general del sistema
    \end{itemize}
    
    \item \textbf{Sensores}
    \begin{itemize}
        \item \texttt{GET /v1/sensors} : Lectura de datos de sensores (temperatura, humedad, pH, CE, etc.)
    \end{itemize}
    
    \item \textbf{Actuadores}
    \begin{itemize}
        \item \texttt{GET /v1/actuators} : Estado actual de los actuadores
        \item POST /v1/actuators - Control de actuadores (bomba, ventilador, luces, calefactor)
    \end{itemize}
    
    \item \textbf{Configuración}
    \begin{itemize}
        \item \texttt{GET /v1/config} : Obtener configuración actual
        \item \texttt{POST /v1/config} : Actualizar configuración
    \end{itemize}
    
    \item \textbf{Registros del Sistema}
    \begin{itemize}
        \item \texttt{GET /v1/logs} : Obtener registros del sistema
        \item \texttt{DELETE /v1/log/clean} : Limpiar registros
    \end{itemize}
\end{itemize}

Todas las peticiones requieren autenticación mediante token, excepto el endpoint de login. El token debe incluirse en el encabezado \texttt{Authorization} de las peticiones posteriores a la autenticación. \subsubsection{Comunicación con la nube}
Se implementó un sistema de envío de datos a un servidor backend mediante peticiones HTTP POST. El sistema utiliza un único endpoint para el envío de datos, con un esquema JSON que incluye todos los parámetros del sistema.

\begin{itemize}
    \item \textbf{Endpoint:} \texttt{http://IP-raspberry-pi/api/v1/telemetry}
    \item \textbf{Método:} POST
    \item \textbf{Autenticación:} Sin autenticación (en fase de pruebas)
    \item \textbf{Formato de los datos:} JSON
\end{itemize}

\textbf{Estructura del cuerpo de la petición}
\begin{verbatim}
{
  "device_id": "hydrogrow-001",
  "timestamp": "2025-03-30T14:12:00Z",
  "sensors": {

    "humidity": 65.2,
    "ph": 6.2,
    "ec": 1.1,
    "light_intensity": 750,
    "water_level": "NORMAL"
  },
  "actuators": {
    "pump": false,
    "fan": true,
    "light": false,
    "heater": false
  },
  "system": {
    "uptime_seconds": 45234
  },
  "alerts": []
}
\end{verbatim}

El servidor de telemetría usa Node.js con Express para recibir datos mediante una API REST. Los datos se guardan en una base de datos PostgreSQL. En esta versión inicial de pruebas no se implementó autenticación ni encriptación, pero están planificadas para versiones futuras.

Se midieron las tensiones de alimentación y los niveles lógicos en cada etapa. Los resultados se mantuvieron dentro de los márgenes de diseño (5.1 V y 3.3 V regulados).

Se verificó el correcto funcionamiento de los diodos zener en las entradas ADC, así como la recuperación del sistema ante cortocircuitos simulados.  
El fusible auto-resetable de 0.5 A se disparó correctamente ante sobrecorriente, restableciendo la operación una vez normalizado el consumo.

\section{Pruebas de integración}

Una vez validados los módulos individuales, se realizaron pruebas de integración para verificar el funcionamiento conjunto del hardware, firmware e interfaz web, con el objetivo de analizar la comunicación y sincronización entre las tareas del firmware —monitores, controladores y servidor embebido—. Estas pruebas permitieron validar la interacción entre los componentes del sistema, la estabilidad de la comunicación en condiciones controladas, la coherencia de los datos transmitidos y la correcta ejecución de las acciones automáticas.

\subsection{Procedimiento}
\begin{itemize}
    \item Se conectaron todos los sensores y actuadores al módulo principal.
    \item Se configuró la interfaz web para habilitar el monitoreo y control remoto.
    \item Se introdujeron variaciones controladas en las variables ambientales (temperatura, humedad, pH) para observar la respuesta del sistema.
    \item Se registraron los tiempos de reacción y la correspondencia entre los valores medidos y las acciones ejecutadas.
\end{itemize}

\subsection{Resultados}
El sistema respondió adecuadamente ante las variaciones simuladas, manteniendo la estabilidad de la comunicación entre módulos y registrando los datos en la interfaz sin pérdida de información.  
Los tiempos de respuesta se mantuvieron dentro de los márgenes establecidos, con un promedio inferior a 5 segundos para la activación automática de los actuadores.

\subsection{Pruebas de Usabilidad – Tree Testing Method}

Con el fin de evaluar la estructura y navegabilidad de la interfaz web del sistema hidropónico, se aplicó la metodología \textit{Tree Testing Method}.  
Esta técnica permitió identificar posibles dificultades en la localización de funciones o configuraciones dentro de la aplicación, independientemente del diseño visual.

\subsubsection*{Objetivo}
Verificar que la organización jerárquica del menú y la disposición de opciones en la aplicación resulten intuitivas y coherentes con las expectativas del usuario final.

\subsubsection*{Metodología}
\begin{itemize}
    \item Se construyó un modelo jerárquico de la interfaz (árbol funcional) que incluía las secciones principales: monitoreo de sensores, control de actuadores, configuración del sistema y ajustes de red.
    \item Se seleccionaron tres usuarios de prueba sin experiencia previa con el sistema.
    \item A cada participante se le asignaron tareas específicas, tales como “Configurar un nuevo horario de riego” o “Consultar el valor de pH actual”.
    \item Se registraron los pasos realizados, los errores cometidos y el tiempo requerido para completar cada tarea.
\end{itemize}

\subsubsection*{Criterios de Evaluación}
\begin{itemize}
    \item \textbf{Tasa de éxito:} porcentaje de tareas completadas correctamente.
    \item \textbf{Profundidad promedio:} número de niveles recorridos en el árbol hasta alcanzar la función deseada.
    \item \textbf{Tiempo promedio de búsqueda:} duración promedio empleada por los usuarios para ubicar cada función.
\end{itemize}

\subsubsection*{Resultados}
El análisis de la prueba arrojó una tasa de éxito del 92\% y una profundidad promedio de 2,3 niveles, lo que refleja una estructura jerárquica eficiente.  
Las principales dificultades se concentraron en la ubicación de las opciones de configuración avanzada, lo que motivó una reestructuración de los menús secundarios para mejorar la accesibilidad.

\subsubsection*{Conclusión}
La evaluación confirmó que la interfaz web es intuitiva y adecuada para el usuario final. Se implementaron ajustes menores en la denominación de secciones y en los accesos directos, optimizando la experiencia general de uso y reduciendo el tiempo promedio de navegación.
